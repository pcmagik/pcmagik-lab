## Goal
Utworzyć bin/po-publikacji.sh: przebudowa HTML i assets/homepage-benchmarks.json wyłącznie z data/episodes.json, automatycznie po publikacji. Bez czytania repo pomiarowego.

## DoD
- `bin/po-publikacji.sh` → kod 0; kolejne uruchomienie daje identyczny wynik.
- `python3 bin/test_publication.py` → PASS: nowy odcinek, najnowsze trzy, zmiana liczb/film/linki, błędny feed i brak pliku nie nadpisują stron.
- Test przeglądarki: prawdziwe dane feedu, brak błędów JS, mobile i fallback; stare pliki modeli bez zmian.

## Zadania
- [ ] [A1] Jeden generator i lokalne szablony: główna, katalog, wszystkie odcinki oraz JSON. Weryfikacja typów, ścieżek i braków przed zapisem. Opisy i dane tylko z feedu; liczby niewysłane nie są dorabiane.
- [ ] [A2] Hook uruchamialny z dowolnego cwd, kompatybilne dotychczasowe komendy bez drugiego źródła; UI dopasowane do liczby dostarczonych prób.
- [ ] [A3] Test publicznego CLI, browser, dokumentacja obsługi, lokalny commit.

## Ryzyka i bramki
- Feed obecnie ma dwóch reprezentantów, nie kohortę n=5 → nie pokazywać ich jako pełnych zakresów ani wyliczać wniosku z jednej pary.
- Brak daty publikacji → data próby z identyfikatora, opisana jako taka; awaryjnie data aktualizacji feedu.
- Niepoprawne dane → niezerowy kod i komunikat, bez nadpisania dotychczasowych wyników.
- Surowe pliki modeli, feed i repo pomiarowe → bez edycji.
- Commit lokalny; push/merge poza zakresem.

- Teraz: lokalne szablony, generator, testy, hook i commit.
