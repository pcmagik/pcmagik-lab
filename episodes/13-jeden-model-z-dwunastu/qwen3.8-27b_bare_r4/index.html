Methodology

How the series measures things

No cherry-picked runs, no mystery settings. Every test in the series follows the same controlled process so the only thing that changes is the thing being tested.

01

Same prompt

Every model in a test gets the exact same prompt. The input never moves — that's the control.

02

Same rig

One single machine for the whole series. Same GPU, same server, same conditions from run to run.

03

One variable per test

Each test changes exactly one variable — so any difference in the output is meaningful, not noise.

04

Model reloaded before every run

The model is reloaded fresh before every run, so no leftover state ever skews a result.

05

Everything published

Every prompt and every result file goes straight to the public repository. Reproduce it yourself.

06

Local, not the cloud

Everything runs on local hardware. No remote inference — the whole point is what your own GPU can do.

The full set of prompts and result files for every test is published in the repository — open it and verify any claim the series makes.
The rig

One rig. No excuses.

The entire series runs on a single workstation. One GPU, one model server — a fixed environment where the only thing in motion is the variable under test.

  • gpuNVIDIA RTX 3090
  • vram24 GB
  • rigs1 — always this one

Model server: LM Studio

Models are served locally with LM Studio, the local model server the whole series is built around. Same server, same machine, every single test.

fixed prompt → model reload → LM Studio → RTX 3090 → result file → repo

The pipeline is deliberately boring: load, run, publish. When the setup this simple still produces different answers between models, that's a signal worth showing on camera.
