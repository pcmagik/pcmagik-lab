TASK HARD — retro BBS forum from the year 2000
RUN MODE: {{RUN_MODE}}

Build "BASEMENT BBS": a web forum styled as a green phosphor terminal, with users, boards, threads, posts, private messages, roles, full-text search, a JSON API and tests.

Stack, fixed:
- Python 3.12 standard library only: `http.server` (ThreadingHTTPServer), `sqlite3` with FTS5, `hashlib`, `secrets`, `html`, `json`, `unittest`. No pip, no third-party packages, no network access at any point.
- Files: `app.py` (server and routes), `db.py` (schema, migrations, queries), `seed.py`, `tests/` (unittest), `static/style.css`, `README.md`. HTML may be produced by Python functions or by a template mechanism of your own; no template libraries.
- `python3 app.py` serves on http://127.0.0.1:8000 with the database file `bbs.sqlite3` created on first start. `python3 -m unittest discover -s tests` must pass.
- UI language: English. Code, identifiers, comments and commit messages in English.

Requirements:
1. Accounts: register (login 3–20 characters, `[a-z0-9_]`; password at least 8 characters), login, logout. Passwords hashed with `hashlib.scrypt` or `pbkdf2_hmac` with a per-user random salt; never stored or logged in plain text. Sessions: random 32-byte token stored server-side, sent as an HttpOnly, SameSite=Lax cookie. Every POST form carries a CSRF token bound to the session; a request without a valid token is rejected with 403. After five failed logins for one login name, that login is locked for 60 seconds.
2. Roles: `user`, `moderator`, `admin`. The first registered account becomes `admin`. Admin can change any user's role, pin and unpin threads, lock and unlock threads, delete any thread or post. Moderator can lock and unlock threads and delete posts. User can create threads and posts and edit own posts; an edited post shows "edited" with the time. Every forbidden action returns 403 with a page in the same terminal style.
3. Boards, fixed and seeded: "Hardware", "Software", "Off-topic". A thread has a title, board, author, creation time, pinned and locked flags. A post has a body, author, creation time and optional edit time. Body is plain text: line breaks are kept, HTML is escaped, URLs starting with http:// or https:// become links. Pinned threads come first, then by last post time. Pagination: 20 threads per page, 20 posts per page. Replying in a locked thread is refused.
4. Private messages: send to a login name, inbox and outbox, unread counter in the header, a message becomes read when opened. A user sees only their own messages.
5. Full-text search: FTS5 virtual table covering thread titles and post bodies, kept in sync with triggers. Tokenizer `unicode61` with `remove_diacritics 2`, so "resume" matches "Résumé" and "cafe" matches "CAFÉ"; a trailing `*` enables prefix search. Results show a `snippet()` with the matched terms highlighted and link to the post anchor inside its thread. Quoted phrases are searched as phrases. Malformed queries return an empty result with a message, never a stack trace.
6. Read-only JSON API, UTF-8, `Content-Type: application/json`: `GET /api/boards`, `GET /api/threads?board=<slug>&page=<n>`, `GET /api/threads/<id>` (thread with its posts), `GET /api/search?q=<text>`. Unknown id returns 404 with `{"error": "not found"}`.
7. Look and feel: black background, green text in the `#33ff33` family, one monospace font, borders built from box-drawing characters, an ASCII-art logo "BASEMENT BBS" in the header, a status line at the bottom showing the logged-in user, unread message count and server time, a blinking block cursor after the logo. All pages work without JavaScript; JavaScript is optional. One stylesheet served by the app at `/static/style.css`.
8. Security: parameterized SQL everywhere, every output escaped, CSRF on every POST, no stack traces or file paths sent to the client (500 shows a short terminal-style page), request bodies limited to 64 KB.
9. Tests: at least these cases: registration and login; the first account becomes admin; thread and post creation; a user cannot lock a thread (403); reply in a locked thread is refused; private message changes the unread counter; search finds a post containing "CAFÉ" via the query "cafe"; `/api/threads/<id>` returns the expected JSON shape. Tests start the server on a free port with a temporary database file and remove it afterwards.
10. Seed: `python3 seed.py` creates the accounts `sysop` (admin, password `sysop1234`), `mod` (moderator, `mod12345`), `guest` (user, `guest12345`), three boards, 12 threads and 40 posts with 2000s IT humour (dial-up, CRT monitors, Pentium III, Windows 98 crashes, floppy disks), and 3 private messages. Seeding twice does not duplicate data. `README.md` documents the two commands and the seeded accounts.
